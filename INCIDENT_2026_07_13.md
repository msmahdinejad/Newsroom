# Incident: M1 Runtime Verification Blocked

**Date**: 2026-07-13  
**Status**: In Progress - Subagents Repairing  
**Severity**: High (blocks M1 completion)

## Summary

M1 implementation completed but runtime verification blocked by two environmental issues:
1. PowerShell encoding corruption (mojibake in status output)
2. PostgreSQL password authentication mismatch

## Root Causes

### Issue A: PowerShell Encoding Corruption
**Symptom**: Scripts contain corrupted UTF-8 checkmark/cross characters (✓✗ → mojibake)  
**Impact**: PowerShell parser failures on scripts/migrate.ps1 and others  
**Root Cause**: Unicode characters written with incorrect encoding or corrupted during file operations  
**Files Affected**: All 14 .ps1 files in scripts/

### Issue B: PostgreSQL Password Mismatch
**Symptom**: `FATAL: password authentication failed for user "newsroom"`  
**Impact**: All database operations fail from Windows Python  
**Root Cause**: Docker volume initialized with different password than currently configured  
**Evidence**:
- Docker exec into container works (container auth is correct)
- Python/Alembic connection fails (application config doesn't match volume)
- Changing `POSTGRES_PASSWORD` in compose.yaml does NOT update existing volume credentials

## Configuration Chain

```
compose.yaml (POSTGRES_PASSWORD: newsroom_dev)
  ↓ (only at volume initialization)
PostgreSQL data volume (internal pg_hba.conf + user password)
  ↓ (connection attempt)
.env (DATABASE_URL with password)
  ↓
Pydantic Settings (settings.database_url)
  ↓
SQLAlchemy engine / Alembic
```

**Mismatch**: Volume was initialized with password X, config now has password Y.

## Resolution Plan

**Workstream A** (PowerShell - subagent dispatched):
1. Replace all Unicode status markers with ASCII: [OK], [ERROR], [WARN], [INFO]
2. Ensure UTF-8 with BOM or ASCII-safe encoding
3. Create scripts/validate-ps1.ps1 to parse all scripts
4. Verify all 14 scripts parse successfully

**Workstream B** (Database - subagent dispatched):
1. Determine safest fix: volume recreation OR ALTER USER
2. Reconcile all password references
3. Document configuration precedence
4. Verify both contexts: Windows→localhost:5432 and future container→postgres:5432
